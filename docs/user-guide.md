# 使用指南

本指南面向在本机使用 ResumeForge 的求职者。安装、启动和版本升级分别见
[README](../README.md#-快速开始) 与 [升级与数据安全](upgrading.md)。

ResumeForge 的推荐流程是：维护完整个人资料 → 录入目标岗位 → 生成或编写岗位版简历 →
预览、微调和导出。AI 生成、岗位需求解读、岗位化建议和求职助手需要配置模型；岗位和资料
的粘贴识别优先使用已配置的模型做结构化抽取，未配置模型或模型不可用时才退回本地规则，因此始终可离线运行。

## 界面导览

| 入口       | 主要用途                                               |
| ---------- | ------------------------------------------------------ |
| 首页       | 查看统计、最近岗位和简历，并跨岗位与简历记录搜索       |
| 岗位广场   | 录入、筛选和管理岗位，从岗位发起简历制作与需求解读；右上角可打开「备选岗位」 |
| 简历中心   | 查看 AI 生成或用户编写的历史版本，编辑、收藏和导出     |
| 投递台     | 自动采集岗位、做岗位匹配度分析并把确认的岗位排队自动投递 |
| 求职进度   | 一家公司一个岗位一条记录，跟进「已投递 → 面试 → Offer」；可从邮件通知识别 |
| 收藏夹     | 集中查看收藏的岗位和简历                               |
| 求职助手   | 多轮求职问答，按需关联项目数据、附件或公开搜索摘要；消息可引用、删除，会话可导出 |
| 模拟面试   | 设定面试官后逐轮作答，结束后查看评分报告与改进建议     |
| 资料箱     | 存放证书、作品、面经、复盘、链接、笔记等零散材料       |
| 工作台     | 「助手技能」与「简历模板」两页：自制技能、复制或导入简历模板并实时预览 |
| 我的资料   | 维护基本信息、多张简历照片、教育、工作、校园、项目、技能和获奖 |
| 事实台账   | 逐条确认哪些话可以对外说：原始事实、承担程度、个人边界与核实状态 |
| 设置       | 配置当前大模型、测试连接、保存多套配置记录、备份数据与检查更新 |
| 使用指南   | 左侧导航底部的常驻入口；首次打开网站时也会自动显示一次 |

首次引导的完成状态只保存在当前浏览器的 `localStorage`，不会写入业务数据库。关闭后不会再次
自动弹出，仍可随时从左侧导航重新打开。

导航底部的 **退出** 会停止后端服务，页面上所有需要后端的功能随之停止；下次使用请在项目目录
重新运行 `start.cmd`。

## 0. 通用操作：拖拽导入与右键菜单

- **拖拽导入**：所有导入入口都支持把文件从资源管理器**直接拖进对应区域**——岗位识别、备选岗位截图、
  资料箱附件、简历照片、助手附件、经历参考文件、技能包、简历模板 HTML、数据集备份包，
  拖拽区贴着对应的按钮或区域。不支持的类型会在页面右上角提示，不会静默忽略。
- **右键菜单**：岗位卡片、简历卡片、资料卡片、助手会话、助手消息、工作台里的模板列表都支持
  在整行/整块上点右键唤出与「更多」相同的操作清单（包括编辑与删除），不必去找行尾的小按钮。

## 1. 配置大模型（可选）

进入 **设置**，点击 **编辑设置**。如果只手动管理岗位、维护资料或自行编写简历，可以跳过本节；使用 AI 生成、岗位需求解读、岗位化建议或求职助手前需要先保存可用配置。

### 使用内置预设

从“快速预设”选择 DeepSeek、豆包、Kimi、OpenAI 或 Ollama，页面会自动填写对应的
`Base URL` 和默认模型名称。云服务按要求填写 API Key；无需鉴权的本地兼容服务可以留空。
根据需要调整创意度、超时时间和最大输出 Token，然后点击 **测试连接**。测试成功后点击
**保存配置**。

### 使用自定义模型

快速预设里有两项不是具体服务商，区别只在**选中时做什么**：

- **自定义模型（OpenAI 兼容）**：保留当前填的内容，只把"当前用的是哪个厂商"改成自定义。
  已经填好接口信息、只是不想挂在某个厂商名下时用它。
- **纯手动配置（不套用任何预设）**：把 `Base URL` 和模型名称**清空**，从空白开始填。
  API Key 不会被清掉。走中转站、公司网关这类地址时，先选它再填更省事。

选择其中任一项后填写：

- `Base URL`：服务根地址（例如以 `/v1` 结尾的地址）或完整的 `/chat/completions` 地址；
- 模型名称：服务商实际接受的模型标识，不是页面上的营销名称；
- API Key：云服务按服务商要求填写；无需鉴权的本地兼容服务可以留空；
- 创意度、超时时间和最大输出 Token：控制输出稳定性、等待时长和单次回复上限；勾选「不限制」后
  不再发送 `max_tokens`，改由服务商决定上限。

接口协议有两种可选。默认的 **OpenAI 兼容（Chat Completions）** 适用于绝大多数服务商，也是
「快速预设」里除 Claude 之外所有条目的协议。要直连 Claude 官方接口则选 **Anthropic 原生（Messages）**：
这一协议下 system 是独立字段，扩展思考（「思考强度」）才真正生效，`Base URL` 填
`https://api.anthropic.com/v1`——本应用会在这个地址后面接 `/messages`，所以 `/v1` 不能省。
「快速预设」里的「Claude（Anthropic 原生协议）」会把地址、模型名和协议一次填好。

选错协议的典型表现是连接测试报 404 或 400：地址看着没问题，但请求打到了对方不存在的路径上。
Gemini 等其他服务的原生协议仍需服务商或本地网关提供 OpenAI 兼容端点。远程地址必须使用 HTTPS，
HTTP 只允许本机回环地址。图片输入是否可用取决于模型和服务商的实际兼容能力。

配置保存后，可在“配置记录”中点击 **保存当前配置** 并命名。以后点击记录旁的 **使用**
即可切换；删除记录不会删除当前正在使用的配置。API Key 保存在本机 SQLite 数据库，读取
配置和记录的普通接口只返回脱敏占位符。点击密钥框右侧的眼睛时，本机后端才会通过禁止缓存的
专用接口临时返回当前密钥；再次隐藏、取消或保存设置、修改 Base URL、切换配置后都会清除前端
显示值。模型调用仍会把任务所需内容发送到所选服务商，请先确认其数据政策。

## 2. 完善个人资料

“我的资料”默认是只读状态。点击 **编辑资料** 后才可修改字段，全部板块共用一个
**保存全部资料** 按钮。

可以逐项填写，也可以使用“粘贴识别”导入一大段个人经历文本。已配置模型时，原文会发送给你选择的
模型服务商，用结构化 Prompt 抽取分区和字段，每条结果都要能在原文中找到依据；未配置模型或模型
失败时自动退回本地规则。
识别只回填可编辑草稿，不会直接覆盖已保存资料；请重点核对组织、角色、日期和经历边界。编辑状态下可拖动大板块，
也可折叠内容后调整同一板块内的教育、工作、校园或项目条目顺序。

识别弹窗里也可以直接**贴截图或选文档**：在输入框里按 Ctrl+V，或点 **添加截图或文档** 选本地文件
（最多 4 个，单个 ≤ 2 MB、合计 ≤ 5 MB；支持截图与 pdf/docx 简历文档）。图片、文档与粘贴的文本
可以一起提交，三边都参与识别。图片识别的行为、限制与核对要求和岗位那两处完全一致，
详见 [用截图或文档识别](#用截图或文档识别)。

### 事实台账：每条能说出去的话，都要回到一个出处

侧栏 **事实台账**（在「我的资料」之后）解决的是另一个问题：资料库记的是**发生过什么**，
台账记的是一条条**能对外说的主张**。每条写清四件事：

| 字段 | 作用 |
| --- | --- |
| 原始事实 | 照实写、不包装。它是之后核对一切表述的基准 |
| 简历表述 | 准备写进简历的版本。**不得比原始事实更强** |
| 承担程度 | 参与 / 负责模块 / 主导方案或交付 / 项目负责人 |
| 个人边界 | 团队做了什么、你做了什么——面试时最容易被追问的地方 |

**核实状态决定用途**，不是决定好坏：

- **已确认** —— 可以作为事实写进正式简历；
- **待确认** —— 只能进草稿，且必须保留 `【待补：…】` 占位符；
- **已过期** —— 内容会随时间变化（在读年级、论文在投状态、Star 数），更新前不作为最新事实；
- **不采用** —— 保留原因供复盘，不进入对外材料。

保存时有一条硬规则：**「已确认」的主张里不允许出现 `【待补】` 这类标记**——两件事不能同时
为真。反过来，"强主张没填面试细节""已确认却没写个人边界"这类只是**建议**，会随条目一起显示，
不会拦住你保存。

**从资料生成**：粘贴一段经历、项目说明或获奖情况，系统会拆成若干条草稿（每条都带它自己的
原始事实摘录），你逐条核对、就地改标题和简历表述，确认后再保存。草稿一律以「待确认」入库，
因为模型抽出来的只是候选。没有配置模型时会按段落本地切分，不做任何改写。

**三条接合点**（这是台账真正的用处）：

1. **生成简历时**，只有「已确认」的条目会作为事实基线交给模型；未确认的说法会被列成
   "禁止使用"，且承担程度与个人边界会约束表述强度（"参与"不会被写成"主导"）。
   台账为空时，生成行为与没有这个功能时完全一致。
2. **导出简历时**，正文里还留着 `【待补：…】` 之类标记的会被拦下，并指出**具体在哪一节**。
   这是为了避免把一份还写着"待补"的 PDF 投出去。弹窗里可以选 **仍要导出草稿**（四种格式与
   浏览器打印都一样）——拦下不等于堵死。
3. **求职助手**可以读台账、帮你新建条目或补充内容，但**改不了核实状态**：一条主张能不能
   进正式简历，必须由你自己判断。

### 面试深挖：这条主张我讲不讲得清？

台账页右上角的 **拿去深挖** 进入 `/claims/drill`。它把台账里**已确认**的条目逐条拿出来
压力测试——不是考八股，而是回答"这条主张我到底讲得清吗、哪里还站不住"。

与「模拟面试」的分工写在页面顶部：模拟面试按轮数推进、结束时给四维度评分报告；**深挖不评总分**，
用证据状态说话。界面和接口里都不会出现任何分数。

**每道题的评分标准在你看到问题之前就定下来**，之后不因答得流利而放宽：

| 契约里的项 | 作用 |
| --- | --- |
| 想验证什么 | 这道题的意图 |
| 必须讲到 | 必须听到哪些证据才算过，问完之前就写好了 |
| 出现这些就该被追问 | 描述空泛时追问的触发条件 |
| 可以结束的条件 | 什么时候这题算问完 |

这份契约在整个会话期间**对你可见**（题卡下方可展开）——它在衡量你，你有权看到它。藏起来才会
让人怀疑"是不是看人下菜碟"。

**证据状态**代替分数：

- **已验证** —— 必要证据都讲到了；
- **部分验证** —— 讲到了一部分，还有明确缺口；
- **未验证** —— 没能提供最低限度的事实；
- **存在矛盾** —— 与台账或前文对不上。

状态**只能凭新证据前进**：答得比上次流利但没说出新事实，不会升级；发现矛盾则会把"已验证"打回原形。
另外，模型说"这次算过了"却**列不出任何证据**时，一律不判成「已验证」——那种"过了"没有任何依据。

**两种反馈方式**（开场时选）：

- **真实模拟**（默认）—— 每题后不念判定，结束时统一复盘。念了会让人按判分标准答题，而不像真面试。
  判定仍如实记录，只是不主动展示。
- **训练模式** —— 每题后立刻给一段简短反馈。

结束后出一份**「该去补什么」的清单**：哪些讲得清、哪些还站不住，行动项落到**补事实 / 补知识 /
降表述**三选一；另有**复练队列**——只收部分验证、未验证、存在矛盾的主张，点「出一道」会**换一个角度**
出新题（变体题 / 反事实题 / 故障题 / 证据题 / 压缩表达）。**复练不重复原题**，因为把上次的答案背一遍
不算会了；出的题不计入本场记录，只给你自己练。

求职助手可以读你的深挖记录帮你复盘（`list_drill_sessions` / `get_drill_report`），但**开不了新的深挖**
——每道题的标准要先按你的主张锁定，而且需要你自己逐轮作答。

### 简历照片：存多张，选一张

右侧「简历照片」面板可以保存多张照片（最多 8 张，JPG/PNG/WebP、每张 ≤ 2 MB）：

- 点缩略图即可把它设为**简历照片**，当前使用的那张会标上「使用中」；
- 上传第一张时会自动成为使用中的那张；
- 删除使用中的照片后会自动接替下一张，全部删完则简历不再带照片；
- 照片只保存在本机数据库，不会发送给模型。

### 资料箱：放还没整理进简历的材料

左侧导航的 **资料箱** 用来收留"以后可能用得上、但现在还没写进简历"的东西：证书、作品说明、
链接、笔记、实习/校园材料。每条资料可以带标题、分类、正文、链接、备注与附件（图片最多 2 张，
文本文件最多 4 个；PDF/Word 请把文字粘贴进正文，程序不保存原始文件）。

资料箱的用途不只是归档：求职助手可以读取这里的条目，所以"帮我把这段经历记下来，之后写简历用"
是有地方落的。分类可以自己输入新名字，检索支持关键词与分类筛选。

### 通用简历：不针对任何岗位的一份

岗位版简历是从资料里**按 JD 筛出来**的。唯一的例外是**奖项**：它不参与岗位相关性筛选，
只要你在资料里填过就会保留（受一页简历的篇幅所限，最多 3 条，超出时按资料录入顺序取前 3 条）。
如果你还在看方向、想先准备一份通用的，或者要投的岗位说不清属于哪一类，就用**通用简历**：
它不关联任何岗位，各方向的经历、校园经历、项目、技能和奖项都会保留下来。

在「我的资料」页最下方有 **通用简历** 卡片（页面右上角也有一个直达按钮，因为资料页很长）。
先填一个名字（留空会自动命名），再选：

- **AI 生成**：从你的资料生成一份跨行业简历。它不做岗位定向，个人总结会概括能力全貌，
  不会出现"面向某某岗位"这类表述。资料较多时，超出单份简历篇幅的部分会被省略，结果上方会
  说明省略了多少条。
- **从头手写**：从资料预填一份草稿，你在编辑器里自己改。不调用模型，也就不需要 API Key。

通用简历可以有多份、各自命名，也可以随时重命名（列表里的铅笔按钮）或删除。它们同时出现在
**简历中心**，那里会把它们标成「通用简历」并显示求职意向，导出方式与岗位简历完全一样。

建议尽量维护完整的事实资料库，而不是只录入某一个岗位需要的内容：

- 基本信息与简历照片；
- 教育经历和核心课程；
- 工作或实习经历；
- 校园经历；
- 项目经历；
- 技能和获奖情况。

每条教育、工作、校园或项目经历都可导入 UTF-8 Markdown/TXT 总结文件，也可直接输入总结
正文。系统保存的是文件名与文本内容，不依赖原文件路径；生成岗位版简历时会从中选择相关
片段。资料照片始终留在本机，只在模型生成完成后加入预览和 HTML 打印内容。

## 3. 录入和管理岗位

在 **岗位广场** 点击 **手动添加**，可以使用两种方式建立岗位：

### 手动填写

直接填写职位名称、公司、地点、岗位类型、职责、任职要求、其他招聘信息、发布时间和投递
链接。职位名称与职位描述是保存所需的基本信息。

### 粘贴完整招聘信息

在弹窗顶部粘贴招聘原文后点击 **识别并填充**。已配置模型时，原文会发送给你选择的模型服务商，
用结构化 Prompt 抽取职位、公司、地点、薪资、类型、发布时间、投递链接、岗位职责、任职要求和其他
招聘信息；模型输出只接受原文可验证的内容，某个字段在原文中找不到依据时改用本地规则的结果。未配置
模型或模型不可用时，全部字段由本地规则解析。**岗位录入与识别本身不访问招聘网站**（自动采集与自动投递是另一条链路，见第 6 节），保存前仍须核对草稿和警告。

识别完成后，输入框下方会**常驻一枚来源标记**（「AI 识别」或「本地规则」），鼠标悬停会说明这个来源
意味着什么。它不会随提示条一起消失——两者可信度不同，AI 识别的字段逐条校验过能在你给的内容里找到
出处，本地规则只是按模式匹配，需要更仔细地核对。来源是对**这一次识别**而言的：改动粘贴的文本后标记
会撤掉，直到再次识别。

#### 一次粘贴多份招聘信息

把一段含多份招聘信息的材料（招聘网站整段复制、群里的聊天记录、一次选中的多张截图与文档）粘进来点
**识别并填充**，如果里面不止一份，界面会切到**确认面板**：每份显示岗位名、公司、地点、薪资与原文摘要，
并默认全部勾选。

- 取消勾选不想保存的那些，点 **保存勾选的 N 份为岗位** 一次性入库；
- 想改字段就先点某一份的 **单独编辑**，它会填进表单，改完保存这一份；
- 点 **返回修改原文** 回到文本再识别一次。

拆分规则：优先由模型按"公司 + 岗位"的组合切分，每份必须给出一段**原样复制的原文**作为字段锚点，
所以不会出现"把 A 公司的要求写进 B 公司"的情况；没有可用模型时退回本地规则，按分隔线（`---`）、
序号小标题（`岗位1：`）或第二个公司标签切分。**切不出来就当作一份**，不会硬拆。

#### 用截图或文档识别

招聘信息常常只有一张图（海报、群里转发的截图、别人发来的 JD 长图），手里的简历也常常是
别人给你导出的 PDF 或 Word。在上面那个文本框里直接按 **Ctrl+V** 就能把剪贴板里的截图贴进来
（配合 Win+Shift+S 截图最顺手），也可以点 **添加截图或文档** 选择本地文件。一次最多 4 个、
单个不超过 2 MB、合计不超过 5 MB：

- **图片**：PNG/JPEG/WebP/GIF/BMP/TIFF，贴进来的图会显示成缩略图，可以逐个删除。BMP、TIFF
  由后端转成 PNG 再交给模型，所以截图工具或扫描仪导出的原始文件可以直接用（TIFF 在浏览器里
  渲染不出来，所以只显示文件名）。
- **文档**：PDF、DOCX。文字由后端在**本机**提取，原始文件不会上传给模型，也不需要多模态模型；
  提取出的文字会和粘贴的文本合并后一起识别——所以**没配置模型时，文档也能被本地规则解析出
  一部分字段**，而截图做不到这一点。
- 图片、文档和粘贴的文本**可以同时给**，三边的内容都会参与识别。

几个需要知道的点：

- **识别图片需要模型支持图片输入。** 不支持时不会报错，而是退回本地规则并提示「可能是当前模型
  不支持图片输入（需要多模态模型）」——本地规则读不了图片，所以这种情况下表单不会被填入内容，
  可以到 **设置** 里换一个支持图片的模型再试。完全没配置模型时也会有明确提示。
- **图片识别的核对要求和文本识别不同。** 文本识别是把模型给出的字段逐字回对到你粘贴的原文；
  图片没有原文，只能先让模型把图里的文字抄录一遍，再要求字段出现在它自己的抄录里。这能拦住
  "凭空编字段"，但拦不住"模型把幻觉写进抄录"。所以识别结果上方有一个默认收起的
  **「查看模型识别到的原文」**，展开就能看到模型到底读到了什么，请对照截图核对后再保存。
  文档走的是文本那条路（提取出的文字就是原文），核对要求与粘贴文本相同。
- **扫描件提取不到文字。** 整页都是图片的 PDF（扫描仪导出、拍照转 PDF）没有文字层，系统会
  明确提示改用截图上传——截图会走图片识别那条路。带密码的 PDF 需要先解除保护。
- 一张图里如果有多条招聘信息（例如岗位列表页的截图），识别会以内容最完整的那一条为准，
  不会把几条拼成一条不存在的记录。

粘贴或截图识别结果只是草稿。请确认：

1. 职位、公司和工作地点没有混入职位编号或页面导航文字；
2. 岗位职责与任职要求分区正确；
3. 招聘发布时间确实来自“发布”语义，而不是网页更新时间；
4. 投递链接属于预期的用人单位官网，岗位仍在有效期内；
5. 福利、团队介绍、部门、职位 ID 和申请流程等内容是否进入“其他招聘信息”。

岗位保存后可以添加备注、收藏、修改投递状态，也可先点击 **选择** 再批量设置状态或删除。
岗位详情支持需求解读、AI 生成简历、自行编写简历、查看关联简历和咨询求职助手。

### 备选岗位：先收下，之后再核对

岗位广场右上角的 **备选岗位** 是一个中转站：看到感兴趣但来不及整理的招聘信息时，把文本粘贴
进去、或上传招聘截图（最多 4 张），先存着。等有空了：

- 点「导入到岗位」会打开正式的岗位表单并预填原文，保存后这条备选标记为「已导入 #id」，还会
  保留在列表里，方便回看它变成了哪个岗位；
- 也可以直接让求职助手"把这条备选导入正式岗位"，它会调用同一套流程（重复导入不会产生第二份）。

### 岗位备注里的图片与来源

添加岗位时可以在备注下方再放两张图片（招聘截图、内推码等，每张 ≤ 2 MB），列表里显示图片数量，
岗位详情的备注区可以放大查看。

保存岗位时，系统会按这次识别用了什么输入，在备注里自动补一行来源标注：
`来源：粘贴文本识别` / `来源：图片识别` / `来源：文档识别`（从备选岗位导入、助手录入也各有标注）。
已经标过的不重复追加；岗位详情的「信息来源」一栏也能直接看到。这条记录只为你自己回溯用。

## 4. 制作、编辑和导出简历

**版面诊断**：简历预览上方会显示"正文占了页面的百分之多少"，以及该按什么顺序改。

| 结论 | 含义 |
| --- | --- |
| 合适 | 单页占用 82%~96%，既不留大片空白也不拥挤 |
| 偏满 | 超过 96%，改两个字就可能溢出一行 |
| 偏空 / 明显太空 | 低于 82% / 60%，页面下方空着一块 |
| 超出所选页数 | 按当前版式需要更多页 |

多页简历另看**末页**：末页低于 70% 说明最后一张几乎是空的，把内容前移或减少页数会更好看。

建议固定按 **重排 → 结构 → 间距/字号 → 精简内容 → 扩页** 的顺序给。这个顺序本身就是规则：先让人调间距、调不好再让人删内容等于让人白改一轮；反过来先说"精简内容"，用户又可能删掉本来放得下的经历。所以只有前面几步都不够时才会提到下一步。

**自动一页**：内容塞不下时（结论是「超出所选页数」）面板右上角才会出现这个按钮。它按「页边距 → 区块间距 → 行高 → 字号」逐档收紧，**每试一档量一次，够放下就停**——不会一步把字号缩到最小。字号最多缩到 12px（≈9pt），这是打印可读性的下限；面板上会提前写明这个下限，不让你按了才知道。

版式已经收到最紧还是放不下时，它会**如实告诉你**"只能精简内容或增加页数"，而不是假装成功。自动一页试出来的方案只写进**这一份简历**，不会去改你在「工作台」里做的格式模板——那个是共用的，而自动一页的结果只对当前这份内容成立。

从岗位详情选择以下一种方式：

- **用 AI 生成简历**：按岗位要求从完整资料和相关总结中筛选事实，可选择是否美化拓展及轻度、
  均衡、深度三个级别；美化不应改变姓名、组织、角色、日期和其他结构事实。
  生成结果统一采用「强动作动词 + 方法 + 结果」的短要点（每条 30 字左右、同一段经历或项目
  最多 6 条，个人总结 2-3 句），并去掉口语、套话和"赋能/抓手/闭环"这类黑话——生成后系统还会
  本机检查一遍，命中黑话会自动改写一次，仍存在时会在结果上提示你。把"参与"写成"主导"这种
  **升格职责范围的改写不会发生**，也不会为了凑 JD 关键词写入你没有的技能。
  生成前还可以定三件与内容无关的事：
  - **最大篇幅**：1-3 页 A4，默认 1 页；这个数字会翻译成"整份简历控制在多少字、每段留几条要点"
    写进生成要求。
  - **字号**：小 / 标准 / 大，默认标准；只影响排版密度。
  - **模板**：经典、现代、精简三套，随时可以在预览里换。
  另外有 **补充要求（选填）**：用一句话说明你的偏好，例如"突出性能优化经历""不要出现'负责…'
  这类空泛表述"。它只影响表达方向，不会改变事实锚定、篇幅上限与防虚构规则。
- **自行编写简历**：从个人资料预填统一的简历编辑器，并在旁边保留岗位职责、要求、技能和
  其他信息，用户自行取舍和修改，不调用大模型。

简历预览按所选篇幅显示（1-3 张 A4）。可使用滚轮缩放，放大后使用抓手拖动；切换到“编辑”模式后，
点击纸面字段会定位到结构化编辑器中的对应内容。已保存简历可以按需生成岗位化修改建议，
建议只供参考，不会自动覆盖正文。

**内容塞不下时不用重新生成**：预览上方会提示"内容超出了 N 页"，并提供「增加到 N 页」「改为小字号」
两个按钮——它们只是按新参数重新渲染同一份内容，不会再次调用模型。换成新模板、调页数或字号也会
写回这条简历记录，下次从简历中心打开时的版式与这次一致。

每次保存都会在简历中心形成独立记录，并标明“AI 生成”或“用户编写”。一个岗位可以关联多份
简历，岗位详情可查看全部对应版本，简历详情也可返回关联岗位。

导出方式：

- **PDF（直接下载）**：主按钮，由后端用系统中文字体排版生成，点一下就开始下载，不经过浏览器打印窗口。
  前提是系统里能找到中文字体（Windows/macOS/Linux 的常见字体都在查找范围内）；找不到时按钮会变成
  「打印 / 另存为 PDF」，并提示可用的替代方式；
- **浏览器打印 / 另存为 PDF**：在「更多格式」里，版式与预览完全一致，适合需要自己调整打印边距时；
- HTML：包含本地简历照片，可在浏览器中打印或另存为 A4 PDF；
- Markdown：不包含照片，适合文本存档和继续编辑；
- JSON：不包含照片，适合结构化备份或后续处理。

## 5. 收藏、岗位解读与求职助手

岗位和简历都可以点击星形按钮收藏，“收藏夹”会分页集中显示两类内容。取消收藏只改变收藏
状态，不会删除原岗位或简历。

“岗位需求解读”只把当前招聘原文发送给设置中的模型，用于生成需求总结、原文证据和通用准备
建议；它不读取个人资料，也不会修改岗位。关闭弹窗后结果不会另存为数据库记录。

求职助手支持多轮历史、Markdown、表格、可点击链接、文本/图片/文档附件以及可选的联网搜索摘要。
每条消息都带发送时间，输入框右侧可以调「思考强度」（对支持思考模式的模型生效，不支持的会被忽略）。
首次进入且没有任何会话时，会自动创建一条带引导内容的默认对话，说明这个助手能做什么、怎么用。

历史会话的「⋮」菜单（也可以直接右键那条会话）提供：置顶、收藏、复制分享链接、重命名、
在新对话中继续、移动到分组、复制会话 ID、归档与删除。几点说明：

- **复制分享链接**得到的是本机应用内的深链（`/assistant?conversation=<会话 id>`），在这台电脑上
  打开就能回到那段对话，不是可发给别人的公网链接；
- **在新对话中继续**会把最近 10 条消息复制到一段新会话（附件只保留文件名提示），用来"从这里分叉"；
- **移动到分组**只是给会话归类，侧栏按分组展示，不影响对话内容；
- **归档**会把会话收进「已归档」筛选，并自动取消置顶；

每条消息**整块右键**（或点行尾的「更多」）可以：**引用这条继续问**、复制内容、删除这条消息。
删除单条后，引用过它的提问仍然保留引用内容——引用存的是当时的快照，不会因为原消息没了而变成空白。
回答下方的参考来源、附件和助手做过的操作也都在消息块里。

要一次删掉几条，点消息区右上角的 **多选**：每条消息左侧出现勾选框，勾好之后在顶部条上点
**删除所选**，确认后一次删完（一次最多 200 条，走的是批量接口，中途失败不会删一半）。
多选期间不弹右键菜单（引用、复制此时用不上）；点「退出多选」或换一条会话即恢复原样。

助手默认只收到当前问题和受限的已完成历史；这些历史记录保存在本地 SQLite，并随数据库备份一起保留；岗位、简历和个人资料必须由用户
在发送前主动选择。资料上下文会移除姓名、电话、邮箱和照片，关联简历只移除照片，因此简历
正文中的姓名和联系方式仍可能发送给模型。

助手还能**直接操作项目里的数据**：它会在你需要时查询岗位、简历、资料箱和个人资料，也能按你的要求
新增或修改岗位、备选岗位、资料箱条目、助手技能与个人资料的基础字段（姓名、电话、城市、求职意向、
个人总结等），还可以调整某份简历的模板、页数与字号。几点需要知道：

- **只在你明确要求时才写入。** 只是让它分析、评价或给建议时，它不会顺手改动数据。
- **它没有任何删除能力。** 需要删除岗位或简历时，请到对应页面操作。
- **结构化条目（教育经历 / 工作经历 / 校园经历 / 项目 / 技能 / 奖项）它只能「追加一条」**，最典型的场景是把资料箱里的材料整理进个人资料（"把那条实习材料整理进我的经历"）。改动或删掉**已有**条目仍要到「我的资料」页面操作。追加成功后建议去页面核对一遍。
- 每次操作都会在回复里以「✓ 新增岗位「…」」这样的形式列出来，点「前往查看」可以跳到对应页面核对；
  历史对话里同样能看到助手当时做了什么。
- 如果你的模型服务商不支持工具调用，助手会自动退化成普通对话，功能不受影响。

### 技能：让助手按你的要求作答

技能是给助手加的一套自定义要求，用来固定你反复交代的偏好。它有两种形态：

- **只有提示词**：一个 `.md` 文件，正文就是要求，例如"帮我改简历时先用 STAR 结构拆解，再逐条指出问题"。
- **提示词 + 知识包**：一个 `.zip`，里面放一份提示词和多份资料，例如面试题库、写作模板、目标岗位的行业术语表。

想自己写一个技能时，到 **技能工作台**（左侧导航）：点「新建技能」填名称、适用场景、提示词，
需要参考资料再加知识文件；页面上有「技能是什么 / 工作台怎么用」的说明和三个可直接改用的模板
（简历要点精炼、面试问题预测、岗位匹配分析）。已有的技能点名称就能看到提示词全文并就地修改——
从设置页的技能列表点进去也是同一个弹窗。

在 **设置 → 助手技能 → 导入技能** 里也可以直接导入文件。`.md` 的正文就是提示词，文件名（或开头的
`---` frontmatter）作为技能名称；`.zip` 需要**有且只有一份**提示词文件——优先用 `SKILL.md`，
其余 `.md` / `.txt` 都当作知识文件：

```
面试模拟官.zip
├── SKILL.md          # 开头写上 name 与 description，正文是提示词
├── 常见题型.md
└── STAR 模板.txt
```

导入后的技能默认启用，可以随时在列表里关掉。需要知道的几点：

- **同名导入会覆盖更新**，提示词和知识文件整体替换，启用状态保留，方便反复调整同一份技能。
- **知识文件不会一次性塞进对话。** 助手只在需要时自己去读相关片段，所以一包几十页的资料不会挤占上下文。
- **技能里的提示词是"要求"，知识文件是"资料"。** 助手会照提示词作答，但知识文件里的文字与岗位描述
  同级，属于参考内容——即使资料里写着"忽略之前的指令"，也不会被当成命令执行。
- 启用过多、提示词过长的技能会超出长度预算：此时被截断或被跳过的技能会在助手的系统提示里点名说明，
  界面上不会悄悄少加载。
- 技能只影响助手，不会改变岗位、简历和资料的任何数据。
- **正在生效的技能会显示在助手页头**（点它直接回到设置管理）；一个都没启用时，新会话的引导区
  会提示这个功能的存在，用过之后就不再出现。

图片附件会在点击发送后立即显示在当前用户消息中，聊天记录中的图片以缩略图展示，点击缩略图
可查看大图。文档附件显示为带图标的文件名（pdf/docx 各一种图标），与图片一样可以放进同一条
消息。附件预览不会改变附件发送限制，也不会把个人资料中的照片自动加入对话。

打开输入框下方的 **联网搜索** 后，助手会先用你的问题自动搜一次（作为开场资料），再拿到一个搜索
工具，能自己决定搜什么、换关键词多搜几次；命中的来源会累积显示在回答下方。关掉开关时搜索工具
不会被下发，助手不会联网。

**一轮回答最多搜 3 次**，这个数字包含开头那次自动搜索——也就是说助手自己还能再搜 2 次。用完
之后工具会明确告诉它"次数已用完"，它会基于已有结果作答并说明信息可能不完整，而不是静默失败。

搜索本身在 **设置 → 联网搜索** 里配置，和上面那个开关是两件事：开关决定"这一次要不要联网"，
设置决定"联网时怎么搜"。

- **搜索来源**：Bing 与 DuckDuckGo 开箱可用，可同时勾选，结果会并发查询后合并去重；SearXNG
  需要填自己的实例地址（公共实例经常限流，所以不预置默认值）。至少要留一个来源。
- **SearXNG 实例地址**：例如 `http://localhost:8080`，必须以 `http://` 或 `https://` 开头。
  不选 SearXNG 来源时可以留空。
- **抓取正文的条数**：默认「只取摘要」，助手只能读到搜索结果的标题、URL 和摘要。改成抓前 1~3 条
  之后，应用会打开排序最靠前的那几条结果页读取正文，助手能拿到更完整的内容（例如招聘页里的
  任职要求全文）。代价是每次搜索更慢，也可能被站点拒绝；被拒绝时那条结果就只剩摘要，不影响
  其余结果。
- **每次返回的结果条数**：1~15 条，默认 8 条。条数越多占用模型的上下文越多。

如果某次搜索什么都没搜到，界面上会说明原因，助手也不会声称自己获得了资料。用人单位官网与招聘页
会排在第三方平台之前。所有招聘信息都应在投递前回到用人单位官网核验。

## 数据、备份与隐私

岗位、资料、照片、简历、收藏、助手历史和模型配置默认保存在
`backend/data/resume_forge.db`。可选服务端环境变量位于 `backend/.env`。两者均被 Git 忽略，
但数据库包含个人信息和明文 API Key，不应提交、分享或放入公开日志。

### 数据集：多份数据与备份

照片、经历参考文件和助手图片附件都以文本形式存在同一个数据库里，所以**一份数据集就是一整份
本地数据**，不需要另外拷贝目录。在 **设置 → 数据集** 里管理：

- **导出当前数据集**：下载 `resumeforge-backup-<时间戳>.zip` 到下载目录（具体位置由浏览器的
  下载设置决定）。导出的是那一刻的一致快照，之后新录入的数据不包含在内。
- **导入备份为新数据集**：选中一个之前导出的 zip，它会变成列表里的一份**新数据集**。导入
  **不会改动你当前正在使用的数据**，所以选错文件也没有损失。
- **切换**：把整个应用切到某份数据集，岗位、个人资料、简历、收藏和助手会话都会变成那份数据
  里的内容。切换后页面会自动重新加载。
- **重命名 / 删除**：名称只用于在列表里区分。删除会把文件移到 `data/datasets/.trash/`，
  需要时可以手动找回；正在使用的那份不能删除。

需要留意：

- **备份中不包含大模型 API Key。** 这是有意为之，避免备份包被分享或长期存放时泄露密钥。
  切到一份从备份导入的数据集后，需要到 **大模型配置** 重新填写 API Key 并测试连接；其余配置、
  岗位、简历和会话都在数据里。
- 每份数据集都是一个完整的数据库副本，会占用与数据库同等大小的磁盘空间；列表里会显示大小。
- 有正在进行的 AI 请求（例如简历生成中）时切换会失败并提示稍后重试——这是为了避免那次请求的
  结果被写进刚切过去的数据集里。
- `backend/data/backups/` 里还留着数据库迁移前的自动备份，**该目录不会自动清理**，确认不再需要
  回滚后可以手动删除较早的文件。

### 简历模板与「工作台」

简历的外观由两件独立的事决定，在 **工作台 → 简历模板** 里管理：

- **样式模板**决定长什么样（配色、字体、标题样式）。内置 6 种：经典 / 现代 / 精简 / 优雅 / 技术 / 极简，
  只读、永远可用。
- **格式模板**决定排得多密（行高、页边距、区块间距、强调色、字号系数）。内置标准 / 紧凑 / 舒展 /
  单色强调四个预设，也可以自制。

两者可以自由组合，"优雅样式 + 紧凑版式"是完全正常的用法。生成简历前和预览时都能随时切换；
切换只**重新渲染**，不会重新调用模型，所以内容不会变、也不额外花钱。

**看效果**：生成弹窗与预览工具栏里的「看效果」会打开模板一览，每个模板都用你的简历（没有简历时
用内置示例内容）真实渲染一页缩略图，还能切字号和版式一起对比，点「用这个模板」直接选用。

**自制样式模板**：在工作台的「样式模板」区点 **复制改一份** 选一个内置模板作为起点（比从空白页
开始容易得多），在左侧改 HTML/CSS，右侧实时预览；也可以点 **导入 HTML** 用一份现成的模板文件。
模板可用 `{{ resume.* }}` 取简历内容、`{{ page_limit }}` 取页数、`{{ base_px }}` 取基准字号，
正文结构可以直接 `{% include "_resume_sections.j2" %}` 复用。保存前的内容都会先渲染一次，语法
写错会当场报错而不是等到导出。导入时脚本与外链会被自动去掉并补上 CSP，渲染在沙箱里进行。

**自制格式模板**：在「格式模板」区点 **自制版式**，只填参数（留空表示沿用样式模板自身的设置），
不用写代码。想"压进一页"时这是最快的办法。

模板名不能与内置或已有模板重名；删除一个自制模板后，用过它的简历会退回默认模板，简历内容不受影响。

### 检查并更新应用

设置页底部的 **软件更新** 可以直接对比本地版本与 GitHub 上的最新发布（只做检查，不会下载或替换
任何文件）；项目根目录的 `update.cmd` 负责真正的更新：

- 从 Git 克隆的目录走 `git pull --ff-only`，再同步前后端依赖；
- 从压缩包安装的目录会下载最新源码并覆盖程序文件，`data/`、`.env`、`runtime/`、虚拟环境与
  前端依赖目录一律不动；
- 想先看它准备做什么：`powershell -File scripts\Update-ResumeForge.ps1 -DryRun`。

更新不会动数据：数据库迁移在下次启动时自动执行，迁移前仍会写一份 `backend/data/backups/` 备份。
**旧版本导出的备份可以在新版本上导入**（导入时会自动把旧结构升级到当前版本），反过来则不行——
来自更新版本的备份会提示"请先升级应用再导入"，这是有意的保护。

更新代码前也可以先运行数据库备份脚本；详细的 Git 更新、压缩包升级、迁移和回滚方法见
[升级与数据安全](upgrading.md)。模型调用和助手联网搜索的完整边界见
[安全政策](../SECURITY.md)。

### 退出应用

侧栏底部的 **退出** 会让后端进程优雅退出（前端随后断开），页面切成"已退出"并告诉你如何重新
启动。它有二次确认——退出会中断正在生成的回复，也会让正在打开的页面失去后端。

不想退出、只想关掉浏览器标签页时直接关掉即可，后端会继续在后台运行，下次打开页面还是原来的
状态。同一台电脑上重复运行 `start.cmd` 不会起第二个后端：启动器检测到已在运行就会跳过。

### 卸载

项目根目录的 `uninstall.cmd` 用来把应用从这台电脑上清掉。它**默认保留你的数据**：

- 删除启动器生成的东西——`backend\.venv`、`frontend\node_modules`、`frontend\dist`、`runtime\`
  以及各类缓存目录；
- **保留** `backend\data`（数据库，含岗位、简历、资料、助手对话）与 `backend\.env`；
- **不会删源码和文档**——它是个卸载器，不是"删掉我的仓库"按钮。想让整个目录消失，跑完之后自己删。

想连数据一起清掉，用 `uninstall.cmd -Purge`；它会先把要删的东西列出来，再要求你手动输入 `YES`
确认（普通卸载同样要确认一次）。加 `-Yes` 可以跳过询问，供脚本调用。

它只在自己的项目目录里工作：放在别处运行时会直接报错退出，不会误删。清理后想重新用，双击
`start.cmd` 会从头装一遍依赖。

## 6. 岗位匹配分析与自动投递

左侧导航 **投递台** 把「自动采集 → 匹配分析 → 排队投递」串成一条链路。它读写的都是岗位广场里已经存在的岗位，本身不产生新的岗位类型；采集与投递是本项目里**少数会主动访问招聘网站**的功能，且只有在你显式触发时才会运行。

投递台顶部常驻一行 **「当前招聘网站：……」**，告诉你现在对接的是哪个招聘网站。目前只支持 BOSS 直聘，后续会陆续增加；新增招聘网站后这一行会自动变，不需要你做任何设置。

### 自动采集岗位

在「投递台 → 自动采集」里填好关键词与城市（至少填一个），可选填最低薪资、经验、学历和单批上限，点 **开始采集**。后端按页抓取岗位并入库，在岗位广场里这些岗位的来源会标注为「岗位采集」。

- **薪资 / 经验 / 学历不一定生效**：关键词、城市和翻页是所有站点都能接受的，而这三项能不能落到查询参数取决于站点本身。无法映射时，采集结果上方会明确标出「以下条件未生效」，提示你这一批没有按这些条件筛选过——不要误以为已经筛干净了。
- 采集到的岗位去重后入库，仍是你熟悉的普通岗位，可在岗位广场里照常筛选、解读与制作简历。采集优先读招聘网站自己的接口数据，所以存下来的**岗位描述是完整版**（页面上有时只显示摘要），薪资也按你在页面上看到的写法保存（如 `20-40K`、`300-800元/天`）；接口读不到时会退回解析页面，两种方式的结果对后续功能没有区别。
- **采到 0 个岗位时，请区分两种情况**：如果页面确实加载出来了、只是关键词没搜到，任务会正常完成并说明「没有找到匹配的岗位」，换个关键词或放宽城市再试即可；如果应用**无法确认页面内容**（页面结构变化、需要登录等），任务会**明确失败**并给出诊断信息（当前地址、页面标题、匹配到的控件数、期望控件），请你把这段信息反馈给维护者以更新站点选择器——**它绝不会把"没抓到"悄悄当成"采到 0 个"**。

### 岗位匹配度分析

在岗位详情里点 **匹配度分析**。它会读取你的**个人资料与简历**，逐条对照招聘要求给出五类结论：**已匹配 / 表达缺口 / 证据不足 / 真实缺口 / 待确认**，并附一条投递建议。结果随岗位保存，投递台据此决定哪些岗位需要你额外确认。

它和只读招聘原文的 **岗位需求解读** 不是一回事：解读回答「岗位要什么」，匹配分析回答「你够不够」。两者互不影响，也都不显示任何百分比评分。分析依据过期或岗位要求改动后，可以按需重新生成。

### 加入队列并投递

1. 在岗位详情点 **加入投递台**。命中**真实缺口**（硬性条件明确不满足）的岗位默认显示为「不投」，需要你逐条确认才能进队；**证据不足 / 待确认**的岗位也必须逐条确认。
2. 在「投递台 → 队列」里调整顺序、选择用哪份简历、预览并修改招呼语。招呼语在真正投出去之前都可以预览和编辑。
3. 先在页面顶部启动 **投递专用浏览器**：它是一个**独立窗口**，启动后会**直接打开招聘网站首页**，请在那里**自己扫码登录**一次。**登录由你在自己的浏览器里完成，应用不保存你的账号密码，也不读取或保存登录 Cookie。** 如果你把这个标签页关掉或跳到了别处，点 **打开招聘网站** 即可找回登录页，不用重启浏览器。想换一个浏览器来跑这个窗口，去「投递设置」里的 **投递台使用的浏览器** 选：自动（优先 Chrome）/ Chrome / Edge / 自定义路径；改完立即生效，不用重启应用。**明确选了某一个浏览器它就只找那一个**——没装会直接告诉你，不会偷偷换成另一个。
4. 点 **开始投递**。执行中逐岗位显示状态（待投递 / 进行中 / 成功 / 失败 / 已跳过）和「已处理 N/M」的计数，**暂停 / 继续 / 停止**按钮常驻。连续失败会自动熔断并醒目提示，处理完问题后可继续。

### 投递记录与失败诊断

「投递台 → 记录」列出每一次投递的结果，可按结果筛选、对单条失败重投。失败会按原因分类（页面结构变化、需要登录、遇到验证码、招呼语缺失、网络超时、简历上传失败等），方便判断是该改配置还是稍后重试。**遇到验证码或安全验证时不会尝试绕过，会如实记为失败并请你手动处理。**

### 隐私边界

- 采集与投递只会访问你显式触发的那一次，不会在后台自动运行；投递专用浏览器使用独立的数据目录，与你的日常浏览器互不干扰。
- **应用不收集、不保存招聘网站的账号密码**；登录凭据只存在于这个独立浏览器窗口里。
- 投递链路的日志不会记录你的账号密码或登录凭据；对外分享日志前仍应自行核对。

## 7. 求职进度

侧栏 **求职进度**（在「投递台」之后）回答的是另一个问题：**投出去之后，对方走到哪一步了**。
投递台记录的是动作，这一页记录的是结果。

一家公司一个岗位只有**一条记录**，它走这样一条线：

```
已投递 → 筛选中 → 测评/笔试 → 面试 → Offer
```

另有 **已结束**（拒信、流程终止）和 **待确认**（材料里说不清楚）两个状态，它们不在这条主线上。

### 记录从哪来

- **投递台投成功的岗位会自动记一条「已投递」**，不用手工再录一遍。
- **从通知导入**：把招聘邮件、短信或站内通知的内容粘进来，也支持按 Ctrl+V 贴截图或上传
  pdf/docx（与岗位识别同一条链路，一次最多 4 个文件）。识别出来后是**预览**——每条写明
  「新增记录 / 更新进度 / 已是最新，未改动」以及**原因**，你勾选确认之后才会写入。
  关闭或取消预览不会写任何数据。
- **手动添加**：自己填公司、岗位、状态和日期。

### 合并规则（两条是硬性的）

1. **状态只会前进，拒信除外。** 乱序粘贴一封三个月前的「申请已收到」，不会把已经在面试的
   进度打回去，界面会说明「这条通知更早，保留现有进度」。收到拒信则直接覆盖当前状态。
2. **普通自动回执不会被读成面试或 Offer。** 「感谢投递」「简历已收到」只会记成「已投递」；
   材料里说不清楚的一律标成「待确认」，等你自己判断。识别不出来时宁可不给结论，也不给一个
   看起来笃定、实际是猜的状态。

合并按**归一化后的「公司 + 岗位」**匹配——去空白、统一大小写、全角转半角。**只做这几件事**：
再加"去掉「有限公司」后缀"之类的规则会把「示例科技」和「示例科技有限公司」合并到一起，
而错误合并比留两条重复更难收拾。

### 看什么

- 顶部五个数字：总数、进行中、本月投递、Offer、已结束。
- **漏斗条**每一级都可以点，点一下就是按那一级筛选。
- 每条记录上的**下一步与截止日期**过了会标红——秋招最容易漏的就是"9 月 20 日前确认面试时间"
  这类带 deadline 的事。
- 「依据」那一行是这条状态从哪句话看出来的原文摘录，方便你核对识别得对不对。
- **导出**：按当前筛选导出 CSV（带 BOM，Excel 直接打开不乱码）或 JSON。

## 8. 模拟面试

左侧导航 **模拟面试** 是"有固定流程的角色扮演"：面试官按你设定的类型、难度与轮数提问，逐轮点评
并追问，结束后给出一份评分报告。它与 **求职助手** 的分工是——助手随问随答，模拟面试按流程走并出分。

### 开一场面试

1. **关联岗位**（选填）：选中后问题会围绕该岗位的招聘要求，并参考你资料里的真实经历提问；
2. **面试类型**：技术面 / 项目深挖 / 行为面（STAR）/ HR 面 / 综合面 / 案例分析 / 英语面试 / 压力面；
3. **难度**与**面试官风格**（严谨专业 / 温和引导 / 持续追问 / 压力质询）；
4. **轮数**：3-12 轮，默认 6 轮；轮数由程序控制，界面上"第 N/6 轮"是准确的；
5. **考察重点**与**自定义面试官人设**（选填）：例如"某大厂后端团队负责人，喜欢追问性能指标与故障处理细节"。

### 作答与复盘

- 一次只问一个问题；答完后面试官先给**80 字以内的点评**（好在哪、最值得改的一点），再问下一题。
- 答不上来可以直接写"不知道"，面试官会给这类问题的回答思路，然后继续问下一个。
- 达到计划轮数会自动收尾；也可以随时点 **结束并出报告** 提前结束。
- 报告包含总分、四个维度（技术/专业能力、表达与结构、岗位匹配度、应变与深度）的评分与依据、
  做得好的地方、可改进的具体建议和一段总评。
- 点 **把这场面试存进资料箱** 会把问答记录与报告整理成一份 Markdown 存进资料箱的「面试复盘」
  分类；之后可以让求职助手读它、总结薄弱点、生成改进计划。

模型调用失败时报告会写明原因，问答记录仍然保留，可以存进资料箱或重新开一场。面试记录与报告
都存在本机数据库，`DELETE` 只删除记录本身。

## 常见问题排查

### 自定义模型连接失败

确认模型标识正确、服务需要鉴权时 API Key 有效，且远程地址使用 HTTPS。
`Base URL` 不应包含账号、密码、查询参数或 URL 片段。先在设置页测试当前表单，再保存配置。
报 404 或 400 时先看「接口协议」是否与服务商匹配：走 OpenAI 兼容接口的服务商要选「OpenAI 兼容」，
直连 Claude 官方接口要选「Anthropic 原生」并把 `Base URL` 填成 `https://api.anthropic.com/v1`。

### 识别后的字段不准确

保留招聘原文，先核对职责和要求的章节标题，再手动修正草稿。不同网站可能把职位编号、部门、
城市和发布日期压缩在同一行，规则无法确认的字段宁可留空也不应猜测。

用截图识别遇到问题时，先展开结果上方的 **「查看模型识别到的原文」**：如果模型把「技术栈」看成了别的字，
或把页面导航文字也抄了进来，多半是截图本身的问题——换成清晰、只框住招聘正文的截图再试，
通常比手工纠正更快。

### 截图识别提示「当前模型不支持图片输入」

说明所选模型只接受文本。到 **设置 → 大模型配置** 换一个支持图片输入（多模态）的模型再试；
此时表单不会被填入任何内容，但之前手填的字段也不会被清空。若提示的是「未配置大模型」，
按上一节完成配置即可。图片本身的限制是单个 2 MB、合计 5 MB——手机拍的招聘展架照片容易超限，
截图一般远小于这个体积。

### 上传图片提示「内容与扩展名不符」

说明这个文件的**名字和真实内容不是一回事**：Windows 只看扩展名，所以浏览器会把它报成 `image/jpeg`，但系统读到的字节并不是 JPEG。最常见的原因是图片站按浏览器偏好返回了 WebP（另存下来名字仍叫 `.jpeg`），也可能是文件被改过名。

**这类文件不用改名，直接上传即可**：系统会按内容判定真实格式并照常识别，附件上会附一句「文件实际是 WebP，已按真实格式处理」告诉你发生了什么。只有在真实格式**不受支持**时才会被拒绝，此时提示里会写明真实格式和处理办法：

- HEIC/HEIF：先在手机、系统相册或图片工具里导出为 JPEG。
- AVIF：先导出为 PNG 或 JPEG。
- 「也识别不出它的实际格式」：文件可能已损坏或被截断，重新导出一次。
- 「实际看起来是 PDF / ZIP 压缩包」：那是一份文档，改名为 `.pdf` / `.docx` 后按文档上传。

（个人照片是唯一的例外：**设置里的简历照片仍要求扩展名与内容一致**，遇到这种情况请先另存为 PNG/JPEG/WebP。）

### 上传的文档没有被识别出内容

先看提示文案：

- **「没有从这份文件里提取到文字」**：这份 PDF 是扫描件或纯图片文件，没有文字层。改用截图
  上传即可——截图会走图片识别（需要多模态模型）。
- **「文件有密码保护」**：先解除 PDF 密码（用阅读器另存为一份不加密的副本）。
- **「文件不是有效的 docx」**：文件其实是旧版 `.doc`，或者扩展名被改过。用 Word 另存为
  `.docx` 或 PDF 后重新上传。
- **「文档内容较长，本次只识别了前一部分」**：文档文字超过了一次识别的上限，把剩下的内容
  复制成文本粘贴进输入框再识别一次即可。

文档识别不需要模型也能工作（文字在本机提取，本地规则照样解析），所以「未配置大模型」时
文档仍会参与识别，只是准确性低于 AI 识别。

### AI 功能提示未配置或输出中断

回到设置页测试当前配置。输出过长时可适当增加最大输出 Token，或勾选「不限制」交由服务商决定
上限——「不限制」并非真的无限，部分服务商的默认值可能比手动设置的值更小。推理型模型会把
思考过程计入输出预算，预算偏紧时正文可能被挤空，这种情况优先考虑「不限制」或更大的值。网络或
模型响应较慢时可增加超时时间；这些参数都会影响成本或等待时间，不会提升模型本身的能力。

### 点「下载 PDF」提示找不到中文字体

服务端生成 PDF 需要系统中文字体：Windows（微软雅黑/黑体/宋体）、macOS（PingFang）、
Linux（Noto CJK/文泉驿）的内置字体都在查找范围内。精简过的 Linux 环境可能一个都没有，这时：

- 用「更多格式 → 浏览器打印 / 另存为 PDF」，版式与预览完全一致；
- 或者设置环境变量 `RESUMEFORGE_PDF_FONT` 指向一个中文 TTF/TTC 字体文件后再启动后端。

### 旧版本导出的备份能在新版本导入吗？

可以。导入时会先把备份里的数据库升级到当前版本再校验，所以旧备份（只要 revision 仍在迁移链上）
都能恢复；反过来，来自更新版本的备份会被拒绝并提示"请先升级应用再导入"，避免用旧代码打开新结构
导致数据损坏。备份里不含大模型 API Key，恢复后需要重新填写并测试连接。

### 「自动采集」会抓取哪些内容？筛选条件都生效吗？

采集会访问招聘网站的搜索页，按关键词和城市翻页抓取岗位列表并入库（来源标注为「岗位采集」）。
关键词、城市和翻页始终生效；**最低薪资、经验、学历能否生效取决于站点**，无法映射时页面会提示
「以下条件未生效」，此时结果里可能包含不满足这些条件的岗位，请以岗位详情为准。采集只在你点
「开始采集」后运行，不会在后台自动抓取。

采集时应用会优先读取招聘网站自己的接口数据，因此存下来的**岗位描述是完整版**、薪资写法与你在
页面上看到的一致；个别情况下接口读不到，应用会退回解析页面内容，两种方式采集到的岗位对后续的
匹配分析、简历制作没有区别。

### 投递台会自动帮我投简历吗？会上传我的什么信息？

只有你在投递台里把岗位排进队列、启动投递专用浏览器并点「开始投递」之后，它才会逐条自动投递。
投递使用你为该岗位选择的简历与招呼语；投递专用浏览器是独立窗口，**登录由你在窗口里自己完成，
应用不保存招聘网站的密码或 Cookie**。遇到验证码或安全验证不会尝试绕过，会记为失败并请你手动处理。

### 为什么提示需要先启动「投递专用浏览器」？

采集和投递都要通过一个由应用单独拉起的浏览器窗口来完成，它使用独立的数据目录、不会碰你的日常
浏览器。请先在「投递台」页面顶部点启动——**这个窗口启动时会直接打开招聘网站首页**，你就在那一页
扫码登录一次，然后再开始采集或投递。

如果启动后看到的是一张空白页，或你把标签页关掉、跳到了别处，点旁边的 **打开招聘网站** 即可重新
打开登录页，不用关掉浏览器重来。

想换浏览器跑这个窗口，去「投递设置 → 投递台使用的浏览器」选择：**自动（优先 Chrome）** 会优先用
Chrome、没装才回退 Edge；**Chrome / Edge** 表示只用这一个，**系统里没装会直接报错**而不会改用另一个
（你选了 Chrome 却启动 Edge 显然不是你想要的）；**自定义路径** 用于绿色版或非默认安装位置。选完立即
生效。

### 提示「没有找到 Google Chrome / Microsoft Edge」怎么办？

这说明你在「投递设置」里把浏览器指定成了某一个（Chrome 或 Edge），但系统里没找到它。三种处理方式：
装上那个浏览器、把设置改回 **自动**（会自动回退另一个）、或改用 **自定义路径** 并填入浏览器可执行
文件的完整路径（必须是真实存在的文件）。**应用不会在你明确选了某个浏览器时静默换成另一个。**

### 采集明明没成功，却显示「共新增 0 个岗位」？

不会了。现在的行为是：**真的没搜到**（页面加载完成、只是关键词太窄）会正常完成并提示「没有找到
匹配的岗位」；**抓不到**（页面结构变化、需要登录、加载超时等）会让任务**明确失败**并给出诊断信息
——当前地址、页面标题、匹配到的控件数、期望控件。请把这段诊断反馈给维护者，用来更新站点选择器。
把"什么都没做"伪装成"完成"是被专门修掉的缺陷。

### 采集/投递会不会开出一堆标签页？

不会。采集与投递全程**复用同一个标签页**导航，不会每采一页或每投一个岗位就新开一个标签页。

### 自动一页按了没反应，或者还是放不下？

三种可能，按概率排：

1. **内容确实太多了。** 一页 A4 大约能放 700~900 个汉字，超得太多时收到最紧也装不下——这时面板会明确说"版式已经收到最紧"，并建议精简内容或加页。
2. **版式已经到下限了。** 页边距 12mm、行高 1.4、字号 12px 是最紧的一组；如果你之前已经手动调到这些值，自动一页就没有可收的了，按钮也不会出现。
3. **那一档量出来还是超高。** 这是正常行为：它会继续试下一档。面板上会显示"正在试第 N/M 档：xxx"，试完十几档需要一两秒。

如果按完之后**预览变了但导出的 PDF 没变**，那是个缺陷，请反馈——预览、导出 HTML 和服务端 PDF 走的是同一份版式配置，三者应该始终一致。

### 字号系数调了，HTML 里为什么看不出来？

不会了。此前「字号系数」只作用于服务端生成的 PDF，HTML 预览里毫无反应；现在它在渲染前就把系数乘进基准字号，所以预览、导出 HTML 和 PDF 三处一致。

需要知道的是：这一项**只有一个入口**（渲染前预乘基准字号），界面上的 CSS 覆盖里没有第二条路。这是刻意的——给两条路会叠乘，界面上调 1.1 会实得 1.21 倍，而这种偏差只有拿尺子量才看得出来。

### 岗位匹配度分析和「岗位需求解读」有什么区别？

「岗位需求解读」只读招聘原文，回答「岗位要什么」；「匹配度分析」会读取你的个人资料与简历，回答
「你够不够」，并给出已匹配 / 表达缺口 / 证据不足 / 真实缺口 / 待确认五类结论。两者都只在你点击后
才生成，也都不显示百分比评分。

### 导出简历时说「还有未完成标记」不给导，怎么办？

说明简历正文里还留着 `【待补：…】`、`【待确认】`、`【待补充】`、`【待核实】` 这类标记——它们
是"这里还没写完"的意思，跟着 PDF 一起投出去就难看了。提示里会指出**具体在哪一节**，去「简历中心」
编辑那份简历，把内容补齐或把标记删掉即可。

只想导出一份草稿自查、并不打算投出去时，在弹窗里选 **仍要导出草稿** 即可；选 **我去改简历**
就什么都不下载。**只有这四种带方括号的写法会被拦下**，正文里正常出现的"待补充说明"之类不会被误伤。

### 事实台账为空，会影响我生成简历吗？

不会。台账为空时不会往生成提示词里加任何东西，生成行为与没有这个功能时完全一致——只有你确认过的
条目才会作为事实基线参与生成。换句话说，台账是"你不维护它就不生效"的东西，不会突然改变已有简历
的结果。

### 求职进度里同一条出现两遍怎么办？

正常情况下不会：记录按「公司 + 岗位」合并，同一组合只有一条。如果你确实看到两条，多半是公司名写
法不同（例如一条写「示例科技」、另一条写「示例科技有限公司」）——应用**刻意不去掉这类后缀**，
因为把两家真实存在的不同公司合并到一起，比留两条重复更难收拾。手工删掉或改名其中一条即可。

### 为什么粘贴旧邮件后进度没有变化？

因为**状态只会前进**。如果那封邮件说的是比当前更早的阶段（比如已经是「面试」了，又导入一封
「申请已收到」），应用会保留较新的结论，并在预览里写明「这条通知更早，保留现有进度」。
这是有意的：否则整理一次邮箱就会把进度冲回三个月前。只有**拒信**会无条件覆盖当前状态。

### 「从通知导入」说没有识别出记录，为什么？

识别需要材料里**同时**出现公司名和岗位名——缺一个就不知道该并到哪一条记录上，猜出来的进度
比没有进度更糟。常见原因是邮件里只写了"您的申请"没有写岗位，或者只截到了正文的一部分。
可以补上完整的邮件正文再试，或者直接点「添加进度」手动填。另外，没配置大模型时会用本地关键词
匹配，判断比较粗；配置模型后识别质量会明显更好。
