# 使用指南

本指南面向在本机使用 ResumeForge 的求职者。安装、启动和版本升级分别见
[README](../README.md#-快速开始) 与 [升级与数据安全](upgrading.md)。

ResumeForge 的推荐流程是：维护完整个人资料 → 录入目标岗位 → 生成或编写岗位版简历 →
预览、微调和导出。AI 生成、岗位需求解读、岗位化建议和求职助手需要配置模型；岗位和资料
的粘贴识别优先使用已配置的模型做结构化抽取，未配置模型或模型不可用时才退回本地规则，因此始终可离线运行。

## 界面导览

| 入口     | 主要用途                                               |
| -------- | ------------------------------------------------------ |
| 首页     | 查看统计、最近岗位和简历，并跨岗位与简历记录搜索       |
| 岗位广场 | 录入、筛选和管理岗位，从岗位发起简历制作与需求解读     |
| 简历中心 | 查看 AI 生成或用户编写的历史版本，编辑、收藏和导出     |
| 收藏夹   | 集中查看收藏的岗位和简历                               |
| 求职助手 | 多轮求职问答，按需关联项目数据、附件或公开搜索摘要     |
| 我的资料 | 维护基本信息、照片、教育、工作、校园、项目、技能和获奖 |
| 设置     | 配置当前大模型、测试连接，并保存多个可切换的配置记录   |
| 使用指南 | 左侧导航底部的常驻入口；首次打开网站时也会自动显示一次 |

首次引导的完成状态只保存在当前浏览器的 `localStorage`，不会写入业务数据库。关闭后不会再次
自动弹出，仍可随时从左侧导航重新打开。

## 1. 配置大模型（可选）

进入 **设置**，点击 **编辑设置**。如果只手动管理岗位、维护资料或自行编写简历，可以跳过本节；使用 AI 生成、岗位需求解读、岗位化建议或求职助手前需要先保存可用配置。

### 使用内置预设

从“快速预设”选择 DeepSeek、豆包、Kimi、OpenAI 或 Ollama，页面会自动填写对应的
`Base URL` 和默认模型名称。云服务按要求填写 API Key；无需鉴权的本地兼容服务可以留空。
根据需要调整创意度、超时时间和最大输出 Token，然后点击 **测试连接**。测试成功后点击
**保存配置**。

### 使用自定义模型

选择 **自定义模型（OpenAI 兼容）**，再填写：

- `Base URL`：服务根地址（例如以 `/v1` 结尾的地址）或完整的 `/chat/completions` 地址；
- 模型名称：服务商实际接受的模型标识，不是页面上的营销名称；
- API Key：云服务按服务商要求填写；无需鉴权的本地兼容服务可以留空；
- 创意度、超时时间和最大输出 Token：控制输出稳定性、等待时长和单次回复上限；勾选「不限制」后
  不再发送 `max_tokens`，改由服务商决定上限。

自定义模型必须兼容 OpenAI Chat Completions 请求和响应格式。Claude、Gemini 等服务的原生
协议不能直接使用，除非服务商或本地网关提供 OpenAI 兼容端点。远程地址必须使用 HTTPS，
HTTP 只允许本机回环地址。图片输入是否可用取决于模型和服务商的实际兼容能力。

配置保存后，可在“配置记录”中点击 **保存当前配置** 并命名。以后点击记录旁的 **使用**
即可切换；删除记录不会删除当前正在使用的配置。API Key 保存在本机 SQLite 数据库，读取
配置和记录的普通接口只返回脱敏占位符。点击密钥框右侧的眼睛时，本机后端才会通过禁止缓存的
专用接口临时返回当前密钥；再次隐藏、取消或保存设置、修改 Base URL、切换配置后都会清除前端
显示值。模型调用仍会把任务所需内容发送到所选服务商，请先确认其数据政策。

## 2. 完善个人资料

“我的资料”默认是只读状态。点击 **编辑资料** 后才可修改字段，全部板块共用一个
**保存全部资料** 按钮。

可以逐项填写，也可以使用“粘贴识别”导入一大段个人经历文本。已配置模型时，原文会发送给你选择的
模型服务商，用结构化 Prompt 抽取分区和字段，每条结果都要能在原文中找到依据；未配置模型或模型
失败时自动退回本地规则。
识别只回填可编辑草稿，不会直接覆盖已保存资料；请重点核对组织、角色、日期和经历边界。编辑状态下可拖动大板块，
也可折叠内容后调整同一板块内的教育、工作、校园或项目条目顺序。

建议尽量维护完整的事实资料库，而不是只录入某一个岗位需要的内容：

- 基本信息与简历照片；
- 教育经历和核心课程；
- 工作或实习经历；
- 校园经历；
- 项目经历；
- 技能和获奖情况。

每条教育、工作、校园或项目经历都可导入 UTF-8 Markdown/TXT 总结文件，也可直接输入总结
正文。系统保存的是文件名与文本内容，不依赖原文件路径；生成岗位版简历时会从中选择相关
片段。资料照片始终留在本机，只在模型生成完成后加入预览和 HTML 打印内容。

## 3. 录入和管理岗位

在 **岗位广场** 点击 **手动添加**，可以使用两种方式建立岗位：

### 手动填写

直接填写职位名称、公司、地点、岗位类型、职责、任职要求、其他招聘信息、发布时间和投递
链接。职位名称与职位描述是保存所需的基本信息。

### 粘贴完整招聘信息

在弹窗顶部粘贴招聘原文后点击 **识别并填充**。已配置模型时，原文会发送给你选择的模型服务商，
用结构化 Prompt 抽取职位、公司、地点、薪资、类型、发布时间、投递链接、岗位职责、任职要求和其他
招聘信息；模型输出只接受原文可验证的内容，某个字段在原文中找不到依据时改用本地规则的结果。未配置
模型或模型不可用时，全部字段由本地规则解析。该功能不访问招聘网站，保存前仍须核对草稿和警告。

粘贴识别结果只是草稿。请确认：

1. 职位、公司和工作地点没有混入职位编号或页面导航文字；
2. 岗位职责与任职要求分区正确；
3. 招聘发布时间确实来自“发布”语义，而不是网页更新时间；
4. 投递链接属于预期的用人单位官网，岗位仍在有效期内；
5. 福利、团队介绍、部门、职位 ID 和申请流程等内容是否进入“其他招聘信息”。

岗位保存后可以添加备注、收藏、修改投递状态，也可先点击 **选择** 再批量设置状态或删除。
岗位详情支持需求解读、AI 生成简历、自行编写简历、查看关联简历和咨询求职助手。

## 4. 制作、编辑和导出简历

从岗位详情选择以下一种方式：

- **用 AI 生成简历**：按岗位要求从完整资料和相关总结中筛选事实，可选择是否美化拓展及轻度、
  均衡、深度三个级别；美化不应改变姓名、组织、角色、日期和其他结构事实。
- **自行编写简历**：从个人资料预填统一的简历编辑器，并在旁边保留岗位职责、要求、技能和
  其他信息，用户自行取舍和修改，不调用大模型。

简历预览固定为一张 A4 纸。可使用滚轮缩放，放大后使用抓手拖动；切换到“编辑”模式后，
点击纸面字段会定位到结构化编辑器中的对应内容。已保存简历可以按需生成岗位化修改建议，
建议只供参考，不会自动覆盖正文。

每次保存都会在简历中心形成独立记录，并标明“AI 生成”或“用户编写”。一个岗位可以关联多份
简历，岗位详情可查看全部对应版本，简历详情也可返回关联岗位。

导出方式：

- HTML：包含本地简历照片，可在浏览器中打印或另存为 A4 PDF；
- Markdown：不包含照片，适合文本存档和继续编辑；
- JSON：不包含照片，适合结构化备份或后续处理。

## 5. 收藏、岗位解读与求职助手

岗位和简历都可以点击星形按钮收藏，“收藏夹”会分页集中显示两类内容。取消收藏只改变收藏
状态，不会删除原岗位或简历。

“岗位需求解读”只把当前招聘原文发送给设置中的模型，用于生成需求总结、原文证据和通用准备
建议；它不读取个人资料，也不会修改岗位。关闭弹窗后结果不会另存为数据库记录。

求职助手支持多轮历史、Markdown、表格、可点击链接、文本或图片附件以及可选的 Bing RSS
公开搜索摘要。历史会话可以通过三点菜单置顶或收藏，置顶会话会自动显示在列表最顶部，侧栏支持按“全部/收藏”筛选；
助手默认只收到当前问题和受限的已完成历史；这些历史记录保存在本地 SQLite，并随数据库备份一起保留；岗位、简历和个人资料必须由用户
在发送前主动选择。资料上下文会移除姓名、电话、邮箱和照片，关联简历只移除照片，因此简历
正文中的姓名和联系方式仍可能发送给模型。

图片附件会在点击发送后立即显示在当前用户消息中，聊天记录中的图片以缩略图展示，点击缩略图
可查看大图。图片预览不会改变附件发送限制，也不会把个人资料中的照片自动加入对话。

联网搜索只读取少量结果的标题、URL 和摘要，不会打开结果网页或自动抓取招聘详情。所有招聘
信息都应在投递前回到用人单位官网核验。

## 数据、备份与隐私

岗位、资料、照片、简历、收藏、助手历史和模型配置默认保存在
`backend/data/resume_forge.db`。可选服务端环境变量位于 `backend/.env`。两者均被 Git 忽略，
但数据库包含个人信息和明文 API Key，不应提交、分享或放入公开日志。

### 导出与恢复

照片、经历参考文件和助手图片附件都以文本形式存在同一个数据库里，所以**一个备份包就是全部
本地数据**，不需要另外拷贝目录。在 **设置 → 数据备份与恢复** 里操作：

1. 点 **导出全部数据**，浏览器会把 `resumeforge-backup-<时间戳>.zip` 下载到下载目录
   （存放位置由浏览器的下载设置决定）。导出的是导出那一刻的一致快照，之后新录入的数据不包含在内。
2. 换电脑或需要恢复时，在新装的 ResumeForge 里点 **导入备份…**，选中这个 zip。
3. 界面会先展示备份的导出时间、来源版本和数据量，确认后才真正覆盖。**恢复前会自动把当前数据库
   备份到 `backend/data/backups/`**，需要回滚时可以从那里取用。

两点需要留意：

- **备份中不包含大模型 API Key。** 这是有意为之，避免备份包被分享或长期存放时泄露密钥。恢复后
  （包括在同一台电脑上恢复）都需要到 **大模型配置** 重新填写 API Key 并测试连接；其余配置、
  岗位、简历和会话都会还原。
- 恢复会**整体替换**当前数据。如果确认弹窗里出现「备份中的数据少于当前数据」的红色提示，说明
  恢复后这部分内容将无法找回，请先确认选对了文件。

更新代码前先运行数据库备份脚本；详细的 Git 更新、压缩包升级、迁移和回滚方法见
[升级与数据安全](upgrading.md)。模型调用和助手联网搜索的完整边界见
[安全政策](../SECURITY.md)。

## 常见问题排查

### 自定义模型连接失败

确认接口兼容 OpenAI Chat Completions、模型标识正确、服务需要鉴权时 API Key 有效，且远程地址使用 HTTPS。
`Base URL` 不应包含账号、密码、查询参数或 URL 片段。先在设置页测试当前表单，再保存配置。

### 识别后的字段不准确

保留招聘原文，先核对职责和要求的章节标题，再手动修正草稿。不同网站可能把职位编号、部门、
城市和发布日期压缩在同一行，规则无法确认的字段宁可留空也不应猜测。

### AI 功能提示未配置或输出中断

回到设置页测试当前配置。输出过长时可适当增加最大输出 Token，或勾选「不限制」交由服务商决定
上限——「不限制」并非真的无限，部分服务商的默认值可能比手动设置的值更小。推理型模型会把
思考过程计入输出预算，预算偏紧时正文可能被挤空，这种情况优先考虑「不限制」或更大的值。网络或
模型响应较慢时可增加超时时间；这些参数都会影响成本或等待时间，不会提升模型本身的能力。
